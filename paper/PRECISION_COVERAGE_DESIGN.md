# 排序精确率与被选单元上的覆盖：设计（2026-11-09，跑之前写定）

来源：`paper/PNAS_ACCEPTANCE_REVIEW.md` 的 E2；用户 2026-11-09"做一下这四个吧"。

## 为什么

Discussion 有一句 "Nor is accurate ranking enough"：扶贫瞄准看精确率（转移支付有多少到了穷人手里），碳汇信用看每个被选值可能离估计多远，也就是覆盖。这句目前只有论证，没有本稿自己的数字。本分析把两者放在同一批被选单元上并列，不新增方法、不改任何已存结果。

## 设定与规则

- 图 2a 的 11 个随机森林设定（`experiments/data.py` 的 `DISPLAY`）。
- 5% 政策方向规则（`top5` 或 `bottom5`，按 `data.py` 的 `POLICY`），K = round(0.05 m)。
- 100 次划分，按 `run_main.py` 的 `one()` 逐位重建：种子 [2027, rep, ALL 中的序号]，40/30/30，地图用 `run_main.fit_mu_sigma`。

## 终点（事先写定）

- **P5（精确率）**：被选单元中，真值属于测试单元里同方向最极端 K 个的比例（真值并列时按含入计）。被选数也是 K，所以 P5 同时是召回率。随机挑选时期望为 0.05。
- **P20**：被选单元中，真值属于同方向最极端 20%（round(0.2 m) 个）的比例。随机期望 0.20。
- **split CP 的覆盖**：分数 |y − μ̂|，α = 0.1，在被选单元上计算。另按"真值是否在最极端 5%"把被选单元分成两组，分别报覆盖。
- **并列的已存数字**：normalized CP 与 JOMI（学生化分数）的覆盖，取自 `results/main_<ds>.csv`；留出 R²，取自 `results/maps_r2_rf_summary.csv`。
- 以上都按 100 次划分合并计数。

## 核查（不通过就不报告）

- 第 0 次划分：选择集合与 `units_<ds>_rep0.npz` 的 `'<rule>|idx'` 相同；μ̂ 与存档相同。
- 每次划分重算的 split CP 覆盖计数，与 `main_<ds>.csv` 中 `'SCP |res|'` 的 `n_sel`、`n_cov` 逐一相等（脚本里 assert）。

## 汇总与解读规则（事先写定）

**主汇总。** P20 ≥ 0.80、而 split CP 覆盖 < 0.85 的设定数。

**描述性汇总。** 11 个设定上，P5 与 |split CP 覆盖 − 0.90| 的 Spearman 秩相关。只报数值，不做检验（n = 11），只进 SI。

**解读。**
- (A) 若至少一个设定的 P5 不低于 11 个设定的中位数，且 split CP 覆盖 < 0.85：在 Discussion 那句里加一个带数字的从句，并引 SI 新条目 [S33]。优先用 FIA；FIA 不满足时，用满足条件的设定里 P5 最高的一个。
- (B) 否则：正文不加数字，结果只进 SI，并把那句交给用户决定是否改写。
- 无论 A 或 B，都在 SI 新增一节一表 [S33]。
